# 전송 실패 상태를 UI와 저장소에 반영

- 상태: 진행 중
- 우선순위: 1차 안정화
- 관련 영역: TCP 전송, 메시지 UI, 채팅 로그

## 왜 고려했는가

현재 구조에서는 메시지를 화면에 먼저 추가한 뒤 전송을 시도합니다. 전송이 실패해도 화면과 저장 로그에는 성공한 메시지처럼 남을 수 있습니다.

사용자 입장에서는 "보낸 것처럼 보였는데 상대가 못 받음"이라는 가장 불편한 문제가 됩니다.

## 현재 원인

- 전송 이벤트가 `async void`에 가까운 흐름으로 동작해 호출자가 결과를 기다리기 어렵습니다.
- `PacketSender`가 예외를 잡고 내부 패킷만 실패 상태로 바꿉니다.
- 화면에 추가된 `ChatMessage` 객체에는 실패 상태가 반영되지 않습니다.
- 그룹 전송은 수신자별 성공/실패를 구분하지 않습니다.

## 해결 방향

- `SendMessageAsync`가 `SendResult`를 반환하도록 변경합니다.
- 전송 시도 즉시 메시지를 화면에 추가하고 `전송중` 상태를 표시합니다.
- UI 메시지에 실패 상태를 표시합니다.
- 성공하면 별도 상태 문구를 표시하지 않습니다.
- 실패 메시지는 재전송할 수 있게 합니다.
- 그룹 메시지는 전체 실패/일부 실패를 구분하고 실패 대상 목록을 확인할 수 있게 합니다.
- 저장 로그에도 실패 상태를 남깁니다.

## 완료 조건

- 오프라인 대상에게 보낸 메시지가 실패로 표시됩니다. 완료
- 전송 시도 직후 `전송중`이 표시되고, 성공하면 상태 표시가 사라집니다. 완료
- 앱 재시작 후에도 실패 상태가 유지됩니다. 완료
- 실패 메시지를 재전송할 수 있습니다. 대기
- 그룹 전송에서 일부 실패를 확인할 수 있습니다. 완료
