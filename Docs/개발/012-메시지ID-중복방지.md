# 메시지 ID 기반 중복 수신 방지

- 상태: 완료
- 우선순위: 2차 구조 개선
- 관련 영역: 메시지 송수신, 채팅 로그, 재전송 기반

## 왜 고려했는가

같은 메시지를 다시 받거나, 이후 재전송 기능을 붙일 때 동일한 메시지가 화면과 저장소에 두 번 쌓일 수 있습니다. 특히 그룹 전송에서 일부 실패/재시도 흐름을 다루려면 메시지 단위 식별자가 먼저 필요합니다.

## 기존 원인

기존 메시지는 발신자 IP, 시간, 내용으로만 사실상 구분되었습니다. 이 방식은 같은 내용의 메시지를 연속으로 보내는 경우와 네트워크 재시도/중복 패킷을 명확히 구분하기 어렵습니다.

## 해결 방향

- `MessageEntity`와 `ChatMessage`에 `MessageId`를 추가합니다.
- 사용자가 전송 버튼을 누른 시점에 메시지 ID를 만들고, 화면 표시 메시지와 TCP 전송 DTO가 같은 ID를 공유합니다.
- SQLite `chat_messages` 테이블에 `message_id` 컬럼을 추가합니다.
- `(room_key, message_id)` 조합에 unique index를 둬 같은 방의 같은 메시지가 중복 저장되지 않게 합니다.
- 같은 `MessageId`가 다시 저장될 때는 실패 상태 같은 후속 상태가 반영될 수 있도록 기존 행을 갱신합니다.
- 수신 시 DB에 이미 같은 `MessageId`가 있으면 화면에 다시 추가하지 않습니다.

## 완료 조건

- 텍스트/파일/이미지 전송 시 화면 메시지와 실제 전송 메시지가 같은 `MessageId`를 사용합니다. 완료
- 1:1/그룹 수신 시 이미 저장된 `MessageId`는 중복 표시하지 않습니다. 완료
- SQLite 저장소에서 같은 `room_key`, `message_id` 조합은 한 번만 저장됩니다. 완료
- 같은 `MessageId`의 상태 갱신은 기존 행에 반영됩니다. 완료
- 구버전 클라이언트처럼 `MessageId`가 없는 메시지는 수신 시 새 ID를 부여하므로 완전한 중복 방지는 어렵습니다. 한계
