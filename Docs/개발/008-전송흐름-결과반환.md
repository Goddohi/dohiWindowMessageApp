# 전송 흐름을 결과 반환 구조로 정리

- 상태: 대기
- 우선순위: 선행 리팩토링
- 관련 영역: 메시지 전송, UI 상태, 실패 처리

## 왜 고려했는가

전송 실패 표시를 제대로 구현하려면 전송 호출자가 성공/실패를 알아야 합니다.

현재는 UI가 메시지를 먼저 추가하고, 전송 이벤트는 비동기 결과를 명확하게 돌려주지 않습니다. 그래서 실패를 화면과 저장소에 반영하기 어렵습니다.

## 현재 원인

- 채팅 UI는 `EventHandler<string>`, `EventHandler<(string FileName, string Base64Content)>`로 전송 요청을 올립니다.
- 이벤트 구독부는 `async` 람다지만 호출자는 완료를 기다리지 않습니다.
- `PacketSender`는 실패를 내부에서 처리하고 예외를 다시 던지지 않습니다.
- `MessengerSender.SendMessageAsync`는 성공/실패 결과를 반환하지 않습니다.

## 해결 방향

- `SendResult` 모델을 추가합니다.
- `PacketSender.SendPacketAsync`가 성공 여부와 오류 메시지를 반환하게 변경합니다.
- `MessengerSender.SendMessageAsync`가 `SendResult`를 반환하게 변경합니다.
- UI는 메시지를 `전송 중`으로 추가한 뒤 결과에 따라 `성공` 또는 `실패`로 갱신합니다.
- 그룹 전송은 대상별 결과를 모읍니다.

## 완료 조건

- 오프라인 대상에게 보낸 메시지가 실패로 표시됩니다.
- 실패 메시지가 저장 로그에도 실패 상태로 남습니다.
- 재전송 버튼을 추가할 수 있는 구조가 됩니다.
- 그룹 메시지 일부 실패를 구분할 수 있습니다.
