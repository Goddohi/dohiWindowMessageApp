# 1:1/그룹 채팅 중복 로직 정리

- 상태: 대기
- 우선순위: 선행 리팩토링
- 관련 영역: 채팅 UI, 파일 전송, 로그 저장

## 왜 고려했는가

`SingleChatTabControl`과 `GroupChatTabControl`은 대상만 다를 뿐 파일 처리, 이미지 처리, 드래그 앤 드롭, 클립보드 이미지, 로그 저장/로드 흐름이 많이 비슷합니다.

중복이 많은 상태에서 전송 실패 표시, 파일 저장 정책, 로그 저장 안정화를 각각 적용하면 같은 수정을 두 곳 이상에 반복해야 합니다.

## 현재 원인

- 두 UserControl이 비슷한 메서드를 독립적으로 가지고 있습니다.
- 파일 크기 제한값과 안내 문구가 서로 다릅니다.
- 로그 저장/로드 코드가 각 컨트롤 안에 있습니다.
- 파일/이미지 수신 표시와 저장 경로 처리도 UI 컨트롤에 묶여 있습니다.

## 해결 방향

무리하게 두 컨트롤을 바로 합치지 않고, 중복 책임을 작은 서비스로 먼저 분리합니다.

분리 후보:

- `ChatLogStore`: 메시지 저장/로드
- `OutgoingFileMessageBuilder`: 파일 읽기, Base64 생성, 이미지 여부 판단
- `ReceivedFileStorage`: 수신 파일 저장 위치와 중복 파일명 처리
- `ChatScrollController`: 스크롤 관련 공통 처리

## 완료 조건

- 로그 저장/로드 코드가 UserControl 밖으로 이동합니다.
- 파일 전송 준비 코드가 한 곳에서 관리됩니다.
- 1:1/그룹 모두 같은 파일 크기 제한 정책을 사용합니다.
- 이후 전송 실패 표시를 한 번의 구조로 적용할 수 있습니다.
