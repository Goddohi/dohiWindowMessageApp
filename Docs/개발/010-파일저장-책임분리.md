# 파일 저장 경로 책임 분리

- 상태: 대기
- 우선순위: 선행 리팩토링
- 관련 영역: 파일 수신, 저장 경로, 파일명 충돌

## 왜 고려했는가

파일 저장 위치와 이름 정책은 사용자 데이터 안정성과 직접 연결됩니다.

현재처럼 `MessageUtil`에 `C:\WalkieDohi` 고정 경로가 있으면 권한 문제, 백업 어려움, 파일명 덮어쓰기 문제가 생기기 쉽습니다.

## 현재 원인

- 수신 파일 저장 경로가 상수로 고정되어 있습니다.
- 파일명 중복 처리와 안전화가 없습니다.
- 이미지와 일반 파일 경로 정책이 `MessageUtil`에 섞여 있습니다.
- UI 컨트롤이 저장 경로를 직접 알아야 합니다.

## 해결 방향

- `ReceivedFileStorage` 클래스를 추가합니다.
- 저장 루트는 `%APPDATA%\WalkieDohi\ReceivedFiles`로 이동합니다.
- 파일명 안전화와 중복 방지 이름 생성을 담당합니다.
- `MessageUtil`은 점진적으로 호환 래퍼로 축소합니다.
- 향후 사용자 선택 다운로드 기능도 이 클래스를 통해 확장합니다.

## 완료 조건

- 파일 저장 경로가 한 클래스에서만 결정됩니다.
- 같은 이름의 파일을 받아도 덮어쓰지 않습니다.
- 채팅 로그의 `ContentPath`가 실제 저장 경로와 일치합니다.
- 기존 경로 파일을 바로 깨뜨리지 않는 호환 정책이 있습니다.
