# 수신 리스너를 MainWindow에서 분리

- 상태: 완료
- 우선순위: 선행 리팩토링
- 관련 영역: 앱 시작, TCP 수신, UI 생명주기

## 왜 고려했는가

TCP 수신은 프로그램이 켜져 있는 동안 항상 동작해야 하는 앱 수준 기능입니다.

기존 구조에서는 `MainWindow` 생성자에서 `PacketReceiver`를 만들고 시작했습니다. 이 방식은 창을 만들지 않으면 수신도 시작되지 않는 구조라 자동 시작, 트레이 대기, 백그라운드 수신 같은 기능과 잘 맞지 않습니다.

## 현재 원인

- `MainWindow`가 사용자 정보, 친구 목록, 채팅방 목록 로드와 수신 리스너 시작까지 모두 담당했습니다.
- `PacketReceiver` 이벤트 처리에서 채팅방 목록 갱신과 UI 반영을 한 번에 처리했습니다.
- 앱 생명주기와 UI 생명주기가 섞여 있어 최소화 시작 문제의 원인이 되었습니다.

## 해결 방향

수신 리스너 시작과 수신 메시지 전처리를 `MessageReceiverService`로 분리합니다.

역할 분리:

- `App`: 사용자 데이터 로드, 수신 서비스 생성/시작/종료
- `MessageReceiverService`: `PacketReceiver` 소유, 수신 메시지 발신자 보정, 채팅방 목록 갱신, UI 이벤트 발행
- `MainWindow`: 수신 서비스 이벤트 구독, 현재 채팅 UI에 메시지 반영

## 해결 내용

- `Core/app/MessageReceiverService.cs`를 추가했습니다.
- `App.OnStartup`에서 사용자 데이터와 친구 목록을 먼저 로드하도록 변경했습니다.
- `App`이 `MessageReceiverService`를 생성하고 시작하도록 변경했습니다.
- `MainWindow`는 `MessageReceiverService.MessageReceived`를 구독해 UI 반영만 담당하도록 변경했습니다.
- `MainWindow`에서 `PacketReceiver` 필드와 `StartReceiver` 메서드를 제거했습니다.

## 남은 한계

수신 리스너 자체는 `MainWindow`에서 분리됐지만, 수신 메시지를 채팅 로그에 저장하고 파일을 내려놓는 흐름은 아직 `ChatRoomListTabControl`과 채팅 UserControl에 남아 있습니다.

그래서 현재 단계에서는 최소화 시작 시 숨김 `MainWindow`를 계속 생성합니다. 다음 구조 개선에서 `ChatLogStore`, `ReceivedFileStorage`를 분리하면 UI 없이도 수신 메시지를 저장할 수 있습니다.

## 완료 조건

- `PacketReceiver` 생성과 시작이 `MainWindow`에서 제거됩니다.
- 앱 시작 시 수신 서비스가 앱 생명주기에서 관리됩니다.
- `MainWindow`는 수신 이벤트를 구독하는 역할만 담당합니다.
- 기존 일반 실행과 `--minimized` 실행에서 수신 포트가 열립니다.
