# 채팅 로그 저장 안정성 개선

- 상태: 대기
- 우선순위: 2차 구조 개선
- 관련 영역: 채팅 로그, 로컬 저장소, 성능

## 왜 고려했는가

채팅 로그는 프로그램의 신뢰성과 직접 연결됩니다. 메시지가 많아져도 느려지지 않고, 저장 중 앱이 종료되어도 로그가 손상되지 않아야 합니다.

## 현재 원인

메시지를 하나 추가할 때마다 당일 로그 파일 전체를 읽고 다시 씁니다. 대화량이 많아질수록 저장 비용이 커지고, 쓰기 중 오류가 발생하면 파일 손상 위험이 있습니다.

## 해결 방향

- 단기적으로 임시 파일에 쓴 뒤 교체하는 원자적 저장 방식을 적용합니다.
- 중기적으로 append 가능한 로그 구조를 검토합니다.
- 장기적으로 SQLite 같은 로컬 DB 도입을 검토합니다.
- 저장 실패 로그를 별도로 남깁니다.

## 완료 조건

- 메시지 수가 늘어도 저장 지연이 체감되지 않습니다.
- 저장 중 예외가 발생해도 기존 로그가 유지됩니다.
- 로그 손상 시 복구 또는 격리 정책이 있습니다.
