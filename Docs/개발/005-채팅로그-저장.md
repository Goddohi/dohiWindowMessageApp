# 채팅 로그 저장 안정성 개선

- 상태: 완료
- 우선순위: 2차 구조 개선
- 관련 영역: 채팅 로그, 로컬 저장소, 성능

## 왜 고려했는가

채팅 로그는 프로그램의 신뢰성과 직접 연결됩니다. 메시지가 많아져도 느려지지 않고, 저장 중 앱이 종료되어도 로그가 손상되지 않아야 합니다.

## 기존 원인

메시지를 하나 추가할 때마다 당일 로그 파일 전체를 읽고 다시 씁니다. 대화량이 많아질수록 저장 비용이 커지고, 쓰기 중 오류가 발생하면 파일 손상 위험이 있습니다.

## 해결 방향

- SQLite 기반 로컬 DB 파일 `%APPDATA%\WalkieDohi\ChatMessages.db`에 메시지를 저장합니다.
- 채팅방별 `room_key`로 1:1 채팅과 그룹 채팅 로그를 분리합니다.
- 메시지는 페이지 단위로 최신 기록부터 불러와, 오래된 기록은 스크롤 상단 도달 시 추가 로드합니다.
- DB 전환 전 `ChatLogs` 파일 로그는 더 이상 읽거나 마이그레이션하지 않습니다.
- 채팅방 나가기/내용 지우기 시 SQLite 로그만 삭제합니다.
- `MessageId`와 `(room_key, message_id)` unique index를 사용해 같은 메시지가 중복 저장되지 않게 합니다.

## 완료 조건

- 메시지 저장 시 당일 로그 파일 전체를 다시 쓰지 않습니다. 완료
- 1:1 채팅과 그룹 채팅이 같은 저장소 구조를 사용합니다. 완료
- DB 전환 전 파일 로그 지원 경로를 제거하고 새 DB 로그만 사용합니다. 완료
- 채팅방 삭제 시 DB 로그도 함께 삭제됩니다. 완료
- 같은 `MessageId`가 중복 저장되지 않고, 같은 ID의 상태 갱신은 기존 행에 반영됩니다. 완료
- 저장 실패 로그 수집과 손상 DB 복구 정책은 별도 후속 항목으로 남깁니다. 대기
