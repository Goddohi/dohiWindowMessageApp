# 개발 계획도

## 프로젝트 목적

WalkieDohi는 별도 메신저 서버를 둘 수 없는 폐쇄망에서 Windows PC 간 메시지와 파일을 주고받기 위한 WPF 기반 메신저입니다.

핵심 제약은 다음과 같습니다.

- 중앙 서버가 없습니다.
- 사용자가 오프라인이면 즉시 전달할 방법이 제한됩니다.
- 친구와 그룹 구성은 현재 IP 중심으로 관리됩니다.
- 파일은 TCP 패킷 안에 Base64 문자열로 포함해 전송합니다.

## 현재 주요 기능

- 1:1 채팅
- 그룹 채팅
- 텍스트, 이미지, 파일 전송
- 친구 목록 관리
- 그룹 생성 및 그룹 채팅방 관리
- 채팅 로그 저장 및 이전 로그 불러오기
- 트레이 아이콘 및 자동 시작
- 이미지/PDF 미리보기
- 텍스트 카운터, 엑셀 셀 수집기
- 숨겨진 미니게임

## 고질 문제 정리

### 1. 자동 시작 최소화 시 수신 리스너가 시작되지 않을 가능성

자동 시작은 `--minimized` 인자로 실행되지만, 최소화 시작 시 `MainWindow`를 만들지 않습니다. 현재 수신 리스너는 `MainWindow` 생성자에서 시작되므로 트레이에만 떠 있는 상태에서는 메시지를 받지 못할 수 있습니다.

개선 방향:

- 수신 리스너를 `MainWindow`에서 분리합니다.
- 앱 시작 시 항상 백그라운드 수신 서비스를 먼저 시작합니다.
- UI는 수신 서비스의 이벤트를 구독하는 방식으로 변경합니다.

### 2. 전송 실패가 화면과 저장 기록에 제대로 반영되지 않음

현재 메시지는 전송 결과를 기다리기 전에 화면과 로그에 추가됩니다. `PacketSender`는 실패를 내부에서 처리하고 예외를 다시 던지지 않아 UI가 실패 여부를 알기 어렵습니다.

개선 방향:

- `SendMessageAsync`가 `SendResult`를 반환하도록 변경합니다.
- UI는 전송 중, 성공, 실패 상태를 명확히 표시합니다.
- 실패 메시지는 재전송할 수 있게 합니다.
- 그룹 전송은 수신자별 성공/실패를 따로 기록합니다.

### 3. 사용자 식별을 IP에 과하게 의존

현재 개인 채팅방 키, 친구 매칭, 그룹 구성원, 메시지 방향 판정이 대부분 IP 기준입니다. DHCP, VPN, 무선/유선 전환, 다중 NIC 환경에서 같은 사용자가 다른 사람처럼 보이거나 대화방이 갈라질 수 있습니다.

개선 방향:

- 사용자 식별 기준을 `UserUuid` 중심으로 전환합니다.
- IP는 현재 접속 주소로만 관리합니다.
- 친구 정보에 `UserUuid`, `LastKnownIp`, `DisplayName`을 분리합니다.
- 기존 IP 기반 데이터는 마이그레이션 로직을 둡니다.

### 4. 파일 전송과 수신 파일 저장 방식의 한계

현재 파일 전체를 메모리에 읽고 Base64 문자열로 변환해 전송합니다. 수신 파일은 `C:\WalkieDohi\ReceivedFiles`에 원래 파일명 그대로 저장됩니다.

개선 방향:

- 수신 파일 저장 위치를 AppData 하위로 이전합니다.
- 파일명 안전화와 중복 방지 이름 생성을 적용합니다.
- 전송 크기 제한 안내와 실제 제한값을 일치시킵니다.
- 큰 파일은 청크 또는 스트리밍 전송 방식으로 전환합니다.
- 파일 수신은 사용자 확인 후 다운로드하는 흐름으로 개선합니다.

### 5. 채팅 기록 저장 성능과 안정성

메시지를 저장할 때마다 당일 로그 파일 전체를 읽고 다시 씁니다. 메시지가 많아지면 느려지고, 저장 중 앱이 종료되면 파일 손상 가능성이 있습니다.

개선 방향:

- append 가능한 로그 구조 또는 SQLite 같은 로컬 저장소를 검토합니다.
- 저장 실패 로그를 남깁니다.
- 파일 쓰기는 임시 파일에 기록 후 교체하는 방식으로 안정화합니다.

### 6. 시간 정보 누락 및 재로드 표시 문제

파일/이미지 메시지 일부 생성자에서 전달받은 timestamp를 실제 `Timestamp`에 반영하지 않아 재로드 시점의 현재 시간처럼 표시될 수 있습니다.

개선 방향:

- 모든 `ChatMessage` 파생 클래스가 전달받은 timestamp를 저장하도록 수정합니다.
- 기존 로그의 시간 누락 데이터는 마이그레이션 또는 fallback 정책을 둡니다.

## 우선순위 로드맵

진행 항목별 상세 판단과 해결 기록은 [개발 진행 목록](./개발/README.md)에 정리합니다.

### 선행 리팩토링

- [완료] 수신 리스너를 `MainWindow`에서 `MessageReceiverService`로 분리
- [완료] 전송 흐름을 결과 반환 구조로 정리
- 1:1/그룹 채팅 중복 로직 정리
- 파일 저장 경로 책임 분리
- 개선 작업과 연결된 빌드 경고 일부 정리

### 1차 안정화

- [완료] 자동 시작 최소화 상태에서도 수신 리스너가 동작하도록 수정
- [진행 중] 전송 성공/실패 결과를 UI와 저장소에 반영
- 파일/이미지 메시지 timestamp 누락 수정
- 그룹 파일 용량 제한값과 안내 문구 불일치 수정
- 수신 파일명 중복 방지 처리

### 2차 구조 개선

- 수신 리스너를 앱 서비스 계층으로 분리
- [완료] 전송 결과 모델 `SendResult` 도입
- 로그 기록을 append 또는 로컬 DB 기반으로 개선
- 포트 변경 시 리스너 재시작 또는 명확한 재시작 정책 적용
- 송수신 실패 로그 수집 기능 추가

### 3차 식별 체계 개선

- 친구/그룹/채팅방 키를 IP 중심에서 `UserUuid` 중심으로 전환
- 기존 IP 기반 데이터 마이그레이션
- 폐쇄망 내 사용자 탐색 기능 추가
- 그룹 구성원 상태 동기화 정책 재설계

### 4차 사용성 개선

- 이미지 다운로드를 자동 저장이 아닌 사용자 선택 방식으로 변경
- 친구별 개인 메모 기능 추가
- 안 읽은 메시지 알림
- 채팅 검색 기능
- 프로그램 버전 및 변경 내용 페이지 추가
- 재미 기능 탭 옵션화
